## Unknown command-line options (P6)

- [x] **Examples refuse options they do not read (2026-10-29).** On 2026-10-25 a `froya_real_data` binary built before `site=`/`nu=` existed ran a farm sweep as plain tides: its parser looked up the keys it knew in a `HashMap` and never looked at the rest. `examples/common/arguments.rs` (`Arguments`) records every key a parser asks for, given or not, and `refuse_unread` errors on the others once the parser is done ("unknown or unused option(s): spinup_hous ..."). `froya_real_data` (with `FarmOptions::parse`), `farm_3d` and `local_time_stepping_farm` use it. The farm's keys count as read only when `site=` is given, so `farm_control=0.1` without a site is refused. Bare words are kept as flags (`wind`), so a misspelt bare flag is refused too; `farm_3d` and `local_time_stepping_farm` dropped them before. Every top-level key in the command lines recorded in `notes/`, `docs/` and `scripts/` parses (the `around=`, `dump=`, `perturb=`, `export=` there are `debug_3d=` fields). Still to port: `wave_growth`, `norkyst_boundary_tides`, `tide_gauge_fit` and `common/dap.rs`'s users (TODO P6).

## Norway out of the core: presets and station lists (2026-11-10, issue #219)

The first two parts of issue #219 (part of #221, the coast-agnostic core). No numerics changed.

- **Presets deleted:** `CoriolisSource2D::norwegian_coast`/`norwegian_coast_beta`, `ShallowWater2D::norwegian_coast`, `WindStress2D::norwegian_winter_storm`/`norwegian_summer`, `AtmosphericPressure2D::norwegian_winter_storm`/`severe_storm`, `SillOverflow2D::norwegian_sill`, `SillWithFriction::norwegian_fjord`, `StraitFriction2D::norwegian_strait` and `TracerBounds::norwegian_coast`. Only the two benches called one (`norwegian_coast`, now `f_plane(1.2e-4)`, the same number); the rest had their own unit tests as their only callers.
- **Named by what they are:** `CoriolisSource2D::f_plane_at_latitude(φ)` (new, beside `beta_plane_at_latitude`; the issue assumed an `at_latitude` that did not exist), `TidalPotential::cartesian(constituents, lon°, lat°)` (was `norwegian_coast`, fixed at 5°E 60°N) and `HarmonicAnalysis::monthly()` (was `norwegian_coast`: M2, S2, N2, K1, O1 with P1 inferred, which is what a month resolves anywhere).
- **Station lists are files:** `analysis::tide_gauge::norwegian_stations` (ten gauges at two-decimal positions: Heimsjø and Bodø ≈ 0.5 km off, Bergen 0.9 km) and `analysis::adcp::norwegian_stations` (four invented "example" moorings) are gone. `io::read_tide_gauge_stations` reads a CSV by its header (`name`, `lat`, `lon`, optional `code`); `scripts/norkyst_tide_gauges.csv` (Kartverket's 17 gauges) is the Norwegian list and is read by a test. This closes P3.1's "fix the approximate `norwegian_stations` positions". The file stays under `scripts/` because three scripts read it there and `data/` is git-ignored.
- **Docs:** the README and `CLAUDE.md` present Norway as the first validation.

**Left of #219: Mausund's tide as defaults** (`TODO.md` P8.12). `[bathymetry.slopes_3d]` defaults to `pond_low_water_m = −1.43`, `high_water_m = 2` and `cliff_depth_m = 20`, `[bathymetry] wall_low_water_m = −2`, `[bathymetry.raster] land_elevation_m = 5` and `free_depth_m = 19` (the summer pycnocline's bottom). The pycnocline is a stratification, not a tide, but it is Frøya's too. Since 2026-11-10 a 3D run whose atlas range exceeds the band is warned (`default_3d_bed_tide_warning`), so another coast is no longer silently wrong when it has an atlas. Deriving the levels from the tide is not bit for bit at Frøya: its atlas's largest amplitude sum is 1.40 m, against −1.43/+2. So that change needs the shipped 3D cases rerun with their scores before and after, which needs the Frøya and Bodø data.
